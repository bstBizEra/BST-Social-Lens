## [Unreleased]

### Added
- **Layer B fix — post dialogs no longer linger (extension 0.7.5).** On group feeds, "View more comments" often opens the post as a modal dialog; the assisted round never closed it, so the run scrolled behind a popup until the operator dismissed it. Now: candidates inside any open dialog are skipped; after each click the round notes dialogs that appeared *because of the click* (`newDialogs`, pure), lets the comments fetch land (`assist.dialogDwellMs`, 2.5 s), then dismisses them via their Close control (`isCloseControl`: en/lo/th, refuses destructive verbs) or Escape, re-checking once after the animation; the next click waits for the dwell so dialogs never stack. Dialogs already open when the round started (the operator's) are never touched. Panel shows "N popups closed"; `assist.closeDialogs` toggles the behaviour.
- **HK-001 step (3): the Actor. lens-api → 0.6.7, extension → 0.7.4.** `app/housekeeping/actor.py` executes only the §9 safe list on OPEN auto-allowed findings: `REEXTRACT`, `RECOMPUTE_SNAPSHOTS` (flag on), `PURGE_BY_POLICY` (frozen policy, protected rows exempt), `MARK_RAW_NEEDED`, `BACKFILL_EVENTS`; bounded (`LENS_HK_MAX_ACTIONS`), `LENS_HK_ACT=0` = observe only. Every action writes exactly one `audit.events` row (`system:housekeeper`, role `system`, action `HOUSEKEEP`, queue `housekeeping` — vocabularies widened additively) and one `housekeeping.actions` row; verify re-runs the checks and resolves findings that no longer detect; failures leave the finding OPEN with the error recorded. `housekeeping.raw_needed` + `GET /raw/needed`: hashes the server holds records for but no raw capture; extension 0.7.4 polls it on sync and re-queues bodies it still holds (status line: "re-requested by server"). Live test: BACKFILL_EVENTS actioned and verified in one run, one audit row per action, second run clean.
- **Extension 0.7.3 — required keywords.** `KeywordSet.require[]`: a post is skipped unless it contains at least one required term, whatever else it matched; default = the intent terms (sell / rent / wanted in Lao, Thai and English), so a post that only names a village (`ບ້ານ…`), a district (`ເມືອງ…`) or a price no longer counts as a listing (57 NON_PROPERTY + 28 PRICE_DISCUSSION of the first 333 records came through that gap). Editable in the side panel ("Required terms"; empty = no requirement); existing saved keyword sets receive the default on load. New "No intent term" tile counts what was dropped. Exclude still wins; the include/min-hits gate is unchanged.
- **HK-001 steps (1)+(2): `housekeeping.*` persistence + lineage. lens-api → 0.6.6.** `app/schema_housekeeping.sql` (applied at startup; lint-clean): `runs`, `watermarks`, `checks`, `findings`, `actions`, `quarantine`, `lifecycle_states`. The Housekeeper loop (`LENS_HK_INTERVAL_MIN`, 30; single-flight; `POST /admin/housekeeping/run?dry_run=`) persists every run: latest watermark per stage, one check row per reconciliation code, findings upserted by identity (`first/last_seen_run_id`, count and observed state refreshed; findings that disappear become `RESOLVED`, never deleted). `GET /housekeeping/findings`, `/housekeeping/status.last_run`. `GET /lineage/{id}` + MCP `lineage` walk L0→L3 from a payload hash, record key, observation, location, decision, property or snapshot over existing keys (Q2), returning producing job/version/run, sightings with context, claim counts, review/decision states — no record text or contacts. MCP now 17 tools. Live test: two runs, last_seen bump, dry run, lineage from four identifier shapes, backfill → finding RESOLVED.
- **SLL-DATA-HK-001 Data Stewardship & Housekeeping v0.1 (draft) + read-only status surface. lens-api → 0.6.5.** Operator-accepted direction (2026-09-18): a permanent stewardship control plane around the 001 pipeline. Contract fixes the authority envelope (HK-I1: detect/measure/reconcile/retry/recompute/quarantine/flag/purge-by-policy; never merge/split properties, change prices/claims/text, override HUMAN decisions, delete protected evidence), lineage from the existing run tables (no new lineage table in v0.1), watermarks, reconciliation checks R-EVID…R-RET, a closed finding vocabulary with quarantine reasons, the safe-action list, lifecycle states (30/90/180 d starting policy), draft `housekeeping.*` DDL and the Data Control Center; keeps 001A's L0–L3 names (finer stages, not new layers) and PostgreSQL+PostGIS. Implemented now, read-only: `app/housekeeping/status.py`, `GET /housekeeping/status`, MCP `housekeeping_status` (15 tools) — computed from run tables and row timestamps; resolution/publish stages report `enabled: false` behind the flag. Live tests on both flag states; pure tests for health thresholds and lifecycle policy.
- **Extension 0.7.2 — sightings + capture targets.** (a) A post is recorded once per *context* (`container:<group id>`, else `page:<host/path>`): a same-context, same-content re-sighting is a repeat — not re-stored, not re-synced, and its raw body is not kept; a new context or changed content is a further sighting (`contexts[]`, `sightings`, `sighting_context` on the record; Dexie v4 upgrade seeds existing rows with their container). Runbook §5a.
- **RULE_V1 → 1.0.1 — first fixes from real capture data (001C).** Three patterns in the first 332 records produced wrong prices/areas: (1) **dot thousands** — `2.500.000ບາດ` parsed as `2.500` + a stray `000ບາດ` = 0 THB, `1.234 ຕາແມັດ` as 1.23 m² → `NUMBER_RE` accepts dot-separated groups and `parse_number` treats `\d{1,3}(\.\d{3})+` as thousands; (2) **zero-width spaces** (U+200B etc., common in Lao text) between the price term/number and the currency word left 26 seven-digit prices without currency → mapped to spaces in the length-preserving regex shadow; (3) **obfuscated amounts** (`1,xxx,000฿`, `+,+++$`, `x.xxx$`) yielded a 0-amount price from the visible tail → number tokens never start mid-token, and a withheld price becomes a `PRICE` claim with `price_withheld: true` (amount 0, confidence 0.6, signal `price_withheld`) that never creates a price observation. Bare single digits near a price term (`ລາຄາ 5`) are no longer price claims. Method-version bump ⇒ the extraction loop re-extracts every record automatically. 6 new tests from masked real patterns.
- **Extension sync fixes after the first real sync (2026-09-17).** (a) Ingest origin host permission: the side panel checks `permissions.contains` for the ingest URL's origin on load and shows a **Grant access** button that calls `permissions.request` from the click (it was declared as `optional_host_permissions` but never requested → cross-origin fetch → CORS preflight → "Failed to fetch"). ## [0.6.0] — 2026-09-16

### Added
- **Assisted navigation (Layer B, ADR-0004)** — optional "Expand comment threads" switch on the Autonomous card. During an auto-scroll run the extension clicks in-page expanders — "View more comments", "View N replies", "See more" and their Lao/Thai variants — with jittered 1.5–3.5s pacing, capped per run (default 30) and per scroll round (default 3). The interceptor captures what the expansion fetches; no new capture path.
- `src/lib/assist.ts`: pure, unit-tested allow-list (`classifyLabel`), navigation guard (`isSamePage`), picker (`pickExpanders`) and pacing. Deny-list blocks Join / Like / Share / Reply / Follow / See all / View post and Lao/Thai equivalents.
- Run stops with reason `navigated` if the page URL changes (SPA pushState included); each element is clicked at most once per run (`ClickLedger`, reset on every Start); only elements on or just below the viewport are considered. `javascript:`/`data:` hrefs are never treated as in-page; a candidate must pass **both** control-semantics and label checks (no hint-only path).
- Side panel shows "threads expanded" alongside the scroll count.
- **Sync now** with nothing to push now verifies the ingest URL + token against `GET /stats` and reports "Connected — nothing to push (server holds N records)" or the HTTP error (401 = token rejected). Previously it returned "Pushed 0 records" without contacting the server.
- Default keyword set extended (OP-Vily, 2026-09-17): + ເນື້ອທີ່, location, google map, lat, long. Applies to fresh installs; existing installs edit *Include terms* in the panel.

### Changed
- Extension → 0.6.0 (package.json, wxt manifest, package-lock). `Settings.assist` (default off) and `AutoProgress.clicks` added; `autoStart` relays both `autoRun` and `assist` config.
